# Test Case Document

## Team 15

Tech Stack: JavaScript (MERN Stack)

## 1. Introduction

This Test Case Document is the companion to the Software Test Plan (STP) for the College Event Management System. It covers manual test cases for each functional requirement (FR), and the non-functional (NFR) and security (SEC) requirements, defined in SRS v1.2, and is aligned with SAD v1.0 (API endpoints in §4.4, error handling in §4.5). Each FR includes Unit (UT), Integration (IT), and System (ST) level test cases, following the naming convention `<FR_ID>_<Type>_<Sequence>` (e.g., `FR01_UT_01`). Non-functional cases follow `NFR_<AREA>_<Sequence>` (e.g., `NFR_PERF_01`) and are listed separately in Section 4.

The results combine the 15 November 2026 backend run and source review with the [18 November final UI verification](#5-final-ui-verification). Pass means the recorded evidence supports the expected result. Fail records an observed or confirmed mismatch. Partial means that only part of the case was verified. Pending means the case still needs its specified environment or fixture.

The 15 November baseline reported 119 backend passes and 93.14% statement, 84.46% branch, 82.75% function and 93.14% line coverage. On 18 November the backend suite ran 131 tests with zero failures, and the client build and lint passed. The coverage figures refer to the 15 November run. PR #20 recorded **72 Pass, 15 Fail, 1 Partial, 7 Pending**. The [follow-up run](#6-follow-up-verification) brings the current totals to **75 Pass, 16 Fail, 3 Partial, 1 Pending**. Earlier observations remain in each case’s Actual Result and Section 5.
